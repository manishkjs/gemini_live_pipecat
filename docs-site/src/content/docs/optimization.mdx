As shown in [Token Economics & Pricing](/gemini_live_pipecat/pricing/), an unmanaged Gemini Live session gets progressively more expensive and slower with every turn because historical audio and static system instructions are re-billed on every turn.

By combining three complementary patterns across the call lifecycle, you can flatten quadratic token growth into a predictable **~$0.031/min** linear run rate while keeping end-to-end voice latency under 600ms even on 60-minute calls.

## Pillar 1: Native sliding-window compression (The 15-minute ceiling breaker)

By default, an uncompressed audio session accumulates ~3,167 audio tokens per minute and hits the hard uncompressed-audio session ceiling at **15 minutes**. Worse, by Minute 3 (Turn 19), every new turn is re-reading 10,000+ historical audio tokens.

Adding `contextWindowCompression` with a `SlidingWindow` to your `LiveConnectConfig` instructs the Gemini Live server to automatically truncate the oldest turns once the context crosses your `trigger_tokens` threshold, while always preserving your `system_instruction`.

<ContextCompressionFlow />

### Production configuration

```python
from google.genai import types

config = types.LiveConnectConfig(
    response_modalities=[types.Modality.AUDIO],
    context_window_compression=types.ContextWindowCompressionConfig(
        # Start pruning oldest turns once the context reaches 5,000 tokens
        trigger_tokens=5000,
        sliding_window=types.SlidingWindow(
            # Retain the most recent 3,500 tokens (Pinned SOP + active turns)
            target_tokens=3500
        ),
    ),
)
```

### Choosing your `trigger_tokens` and `target_tokens`
- **High-efficiency telephony default (`5,000 / 3,500`)**: Set `trigger_tokens=5000`, `target_tokens=3500` to flush stale `$3.00/1M` caller audio early and keep Time-to-First-Audio-Byte fast (keep your pinned `systemInstruction` + tool schemas under ~1,500 tokens so they fit comfortably inside the 3,500-token target window). Pair with **Pillar 3 (FactStore)** so critical details from Minute 1 survive FIFO eviction.
- **Extended raw-context window (`16,000 / 10,000`)**: If your workflow does not maintain a client-side `FactStore` and needs 4 to 5 minutes of verbatim unpruned audio history in the window, increase `trigger_tokens=16000` and `target_tokens=10000`.

## Pillar 2: Dynamic prompt cards & phase gates (The Silent Conductor)

In a multi-turn call, your system prompt and tool schemas are re-read on **every single turn**. If you load a monolithic 4,500-token system prompt covering Greeting, KYC Verification, Troubleshooting, Billing, Upsell, and Cancellation at Turn 1, you pay to re-read all 4,500 tokens on every turn, even when the caller hangs up in the first 5 seconds.

Instead, start the session with a compact **120-token opening card** (plus base scaffolding, keeping active prompt tokens averaging **~500 tokens** across phases) and inject modular **Phase Cards** only when the conversation enters a new stage.

<PromptCardFunnel />

### Implementation rules for `clientContent` and phase updates
1. **Only inject between turns**: Sending a `clientContent` frame while the model is actively generating audio will **interrupt and cut off** the model's current speech. Always return phase cards inside a `toolResponse` (`scheduling=WHEN_IDLE`) or inject them via `clientContent` (`turn_complete=False`) immediately after receiving `turnComplete`.
2. **Never use square brackets**: As documented in [Configuration reference -> Prompting for native audio models](/gemini_live_pipecat/gemini-live-configuration/#prompting-for-native-audio-models), native audio models treat bracketed text as vocal stage directions or read them aloud. Use natural, unbracketed prose.

### Code pattern: Advancing phase cards via a tool response

```python
from google.genai import types

PHASE_CARDS = {
    "kyc_verification": (
        "Current conversation phase: Identity Verification. "
        "Ask the caller for their date of birth and billing postal code. "
        "Once verified via verify_caller_identity, advance to troubleshooting."
    ),
    "troubleshooting": (
        "Current conversation phase: Technical Troubleshooting. "
        "Check router telemetry first, then guide the caller through one step at a time."
    ),
    "resolution": (
        "Current conversation phase: Resolution & Wrap-Up. "
        "Confirm the issue is resolved, read back the ticket number, and wish the caller a good day."
    ),
}

async def handle_advance_phase(session, tool_call, next_phase: str):
    card_instructions = PHASE_CARDS.get(next_phase, "")
    # Return the phase instructions inside a WHEN_IDLE toolResponse
    # so the model absorbs the new phase rules without interrupting active speech
    await session.send(
        input=types.LiveClientToolResponse(
            function_responses=[
                types.FunctionResponse(
                    id=tool_call.id,
                    name="advance_conversation_phase",
                    response={"active_phase": next_phase, "guidance": card_instructions},
                    scheduling=types.FunctionResponseScheduling.WHEN_IDLE,
                )
            ]
        )
    )
```

## Pillar 3: Lossless history pruning & session rotation

When Pillar 1 (`SlidingWindow`) drops old audio turns at the `5,000-token` boundary, any facts spoken in Turn 1 (such as the caller's name, postal code, or stated symptom) fall out of the raw audio window. Raw audio tokens (`$3.00/1M`, ~1,668 tok/min) are **4× more expensive per token** and **6× more verbose** than a text transcript (`$0.75/1M` text input).

By converting older audio turns into compact text transcripts and extracting key facts into a lightweight backend `FactStore` (**under 60 text tokens**), you can let the `5,000-token` sliding window evict stale audio while retaining **100% lossless memory** of every detail the caller shared.

<LosslessPruningFlow />

### Code pattern: Maintaining a `<60-token` `FactStore` across window eviction

```python
import json
from google.genai import types

class CallFactStore:
    def __init__(self):
        self.facts = {
            "caller_name": None,
            "postal_code": None,
            "verified": False,
            "issue": None,
        }

    def render_context_summary(self) -> str:
        # Compact JSON stays under 60 tokens at $0.75/1M text input
        return (
            "Verified facts from earlier in this call: "
            f"{json.dumps(self.facts, ensure_ascii=False)}"
        )

# Inject after turnComplete so the FactStore survives FIFO sliding-window eviction:
async def inject_fact_summary_between_turns(session, fact_store: CallFactStore):
    await session.send(
        input=types.LiveClientContent(
            turns=[
                types.Content(
                    role="user",
                    parts=[types.Part.from_text(text=fact_store.render_context_summary())]
                )
            ],
            turn_complete=False,  # Append to context without triggering a new spoken turn
        )
    )
```

## Pre-speech compliance guardrails (200ms jitter buffer)

In strictly regulated industries (banking collections, healthcare triage, insurance underwriting), compliance teams sometimes ask: *"How do we guarantee the native audio model never speaks a prohibited phrase or leaks PII?"*

Because Gemini Live emits `outputTranscription` chunks concurrently with `inlineData` audio frames:
1. Hold outbound 24kHz PCM audio frames in a **150ms to 200ms ring buffer** in your media gateway (Pipecat `FrameProcessor` or custom WebSocket proxy).
2. Run a fast deterministic regex / Aho-Corasick guardrail check against the streaming `outputTranscription` text.
3. If a prohibited pattern is detected, immediately flush the 200ms ring buffer before the audio reaches the telephony socket and trigger a corrective prompt or human transfer.
