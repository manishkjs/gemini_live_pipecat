As shown in [Token Economics & Pricing](/gemini_live_pipecat/pricing/), an unmanaged Gemini Live session gets progressively more expensive and slower with every turn because historical audio and static system instructions are re-billed on every turn.

By combining the first three pillars across the call lifecycle, you flatten quadratic token growth into a predictable `~$0.031/min` linear run rate while keeping end-to-end voice latency under 600ms even on 60-minute calls. The fourth pillar, cached TTS, removes the cost and wait of lines that are the same on every call.

<div class="hero-card">
  <span class="badge badge-blue">Key Architectural Takeaways</span>
  <h3>Two rules that save the most tokens on multi-step calls</h3>
  <p>
    <strong>1. Replace instructions in place, don't stack cards in history:</strong> A prompt card sent as a <code>role="user"</code> turn or inside a tool result stays in conversation history and is billed again on every later turn (<code>2,493 tokens/turn</code> after 3 swaps). Sending it as a system instruction (<code>role="system"</code> or <code>context_update</code>) overwrites the old card in place (<code>783 tokens/turn</code>) and survives 5,000-token sliding-window compaction.
  </p>
  <p>
    <strong>2. Swap per-card tools and instructions with no reconnect:</strong> On Vertex AI <code>gemini-3.8-live</code>, the WebSocket accepts a mid-session <code>context_update</code> message that replaces both the declared <code>tools</code> list and <code>systemInstruction</code> in place. See <a href="/gemini_live_pipecat/optimization/prompt-cards/">Pillar 2: Dynamic Prompt Cards &amp; Per-Card Tools</a> for the animated walkthrough and 8-card flight-booking breakdown.
  </p>
</div>

## Summary across all 4 Pillars

| Pillar | What it fixes | Mechanism | Measured impact |
| :--- | :--- | :--- | :--- |
| <span id="pillar-1-native-sliding-window-compression-the-15-minute-ceiling-breaker">[Pillar 1: Sliding Window](/gemini_live_pipecat/optimization/sliding-window/)</span> | Unbounded carried audio (`~1,840 tok/min`) &amp; 15-min ceiling | `SlidingWindow(5000 / 3500)` FIFO turn eviction | Caps active context at 3,500–5,000 tokens |
| <span id="pillar-2-dynamic-prompt-cards--phase-gates-the-silent-conductor">[Pillar 2: Prompt Cards &amp; Tools](/gemini_live_pipecat/optimization/prompt-cards/)</span> | Paying for all phase prompts &amp; all tool schemas on every turn | `role="system"` or `context_update` in-place replacement | `783 tok/turn` vs. `2,493` stacked; `146–1,091` tool tok vs. `2,198` |
| <span id="pillar-3-lossless-history-pruning--session-rotation">[Pillar 3: Lossless Fact Pruning](/gemini_live_pipecat/optimization/history-pruning/)</span> | Caller details from Turn 1 lost when `SlidingWindow` trims audio | `<60-token` `FactStore` synced into `systemInstruction` | 90%+ history reduction at `$0.50–$0.75/1M` text rate |
| <span id="pre-speech-compliance-guardrails-200ms-jitter-buffer">[Pillar 4: Cached TTS &amp; Guardrails](/gemini_live_pipecat/optimization/cached-tts/)</span> | Paying `$12/1M` + `$3/1M` carried audio for identical greetings | Seed `role="model"` text turn + stream cached 24kHz PCM | `$0.0078` saved per 10-turn call (`$780` per 100k calls) |
