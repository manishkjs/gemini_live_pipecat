As detailed in the companion concept guide ([Telephony pricing &amp; tokenomics](/gemini_live_pipecat/pricing/)), bidirectional voice sessions face four compounding cost forces:
1. **Per-Turn Context Re-Evaluation ("The Photocopier Tax")**: Every back-and-forth turn or caller interruption triggers a full re-evaluation of active prompt instructions and conversation history.
2. **Modal Memory Asymmetry**: While assistant speech automatically collapses to cheap text transcripts (**\$0.75/M**), caller spoken audio accumulates in context as **raw audio tokens at \$3.00/M** (4&times; to 6&times; more expensive per word).
3. **Zero Default Prompt Caching**: Real-time WebSocket streams evaluate carried context on demand (`cached_content_token_count: 0`) alongside fixed model-side scaffolding (~500 tokens/turn).
4. **The 0–5s Telephony Drop Curve**: 30%–50% of phone calls drop in the first 5 seconds, turning heavy upfront prompts into pure waste.

This engineering guide demonstrates how to eliminate all four cost forces using a **3-Pillar Production Architecture**, bringing blended real-world telephony costs right back down to **~\$0.028 – \$0.035 / minute**.

## Pillar 1: Context Window Compression

<Aside type="tip" title="Mental Model: Sticky Note on a Shredder">
  Imagine your conversation history feeding into an automatic shredder set to trigger at **5,000 tokens**. Older pages are shredded so your per-turn photocopy bill never grows above 5,000 tokens—while your system instruction and a tiny **FactStore sticky note (`under 60 tokens`)** stay pinned safely at the top.
</Aside>

### Server-Side Compaction: The Safety Net

Gemini Live provides built-in sliding-window context compression configured in `BidiGenerateContentSetup`. It is **not** an LLM summarizer; it is a deterministic **FIFO sliding window** that evicts the oldest conversation turns when context crosses a token threshold.

| Field | What It Does | Default | Production Target |
| --- | --- | --- | --- |
| `trigger_tokens` | Compaction fires when context crosses this count | ~80% of window (~32k) | **`5000`** (aggressive voice prune) |
| `sliding_window.target_tokens` | How far context shrinks when compaction triggers | `trigger_tokens / 2` | **`3500` – `4000`** |

System instructions and pinned prefix turns are always preserved; older turns are **FIFO-evicted**.

---

### Why Context Optimization Matters More with Large System Instructions

If your agent uses a massive system prompt (2,000–5,000+ tokens of enterprise SOPs, product catalogs, schema specifications, and compliance rules), context optimization is **exponentially more critical**.

Because Gemini Live does not discount carried system prompts across turns, that 4,000-token instruction is billed on Turn 1, Turn 2, Turn 10, and Turn 30. Over a 10-turn call, a 4,000-token prompt alone consumes **40,000 prompt tokens** before counting a single second of user audio:

```text
Prompt Token Tax = Number of Turns × System Instruction Tokens
```

When initial instructions are heavy, letting history accumulate unchecked accelerates quadratic cost explosion. Keeping context trimmed is the only way to prevent baseline prompt overhead from dominating call unit economics.

---

### 5k Compression: The "Blessing in Disguise"

Most developers configure high triggers (`32,000` tokens), fearing that compacting at `5,000` tokens will drop conversation history prematurely.

In duplex voice, **setting `trigger_tokens: 5000` is a massive blessing in disguise**:

1. **Slashes the Expensive Audio Input Cache**:
   Caller speech costs **\$3.00 per million tokens** and remains in the context window as raw audio tokens.
2. **Halts Quadratic Audio Re-billing**:
   Without fast compaction, 2 minutes of user speech (~3,000 audio tokens) is re-billed at \$3.00/M on *every subsequent turn*. Over a 15-turn session, that audio cache is billed over and over again.
3. **The Blessing**:
   Firing compaction at **5,000 tokens** aggressively flushes older raw audio turns from the prompt cache. The model retains the pinned system instruction and the last few immediate dialog turns, cutting prompt token volume by **60% to 75%** and keeping Time-to-First-Audio-Byte (TTFB) fast.

<ContextCompressionFlow />

```python
# Production Vertex AI / AI Studio Live Session Configuration
context_window_compression = {
    "enabled": True,
    "trigger_tokens": 5000,   # "Blessing in disguise": flushes raw user audio cache early
    "sliding_window": {
        "target_tokens": 3500 # Drops ~1.5k tokens of stale audio, retaining recent turns
    }
}
```

<Aside type="tip" title="Tuning Rule of Thumb">
  Never leave `target_tokens` unset. The default drops 50% of the entire window (`trigger_tokens / 2`). Explicitly set `target_tokens` to `trigger_tokens - 1500` so it trims only the oldest audio turns while leaving recent conversational context intact.
</Aside>

## Pillar 2: Just-in-Time (JIT) Prompt Cards

<Aside type="tip" title="Mental Model: Flashcards vs. Encyclopedia">
  Don't hand the AI a 50-page encyclopedia on Turn 1 just to say *"Hello, am I speaking with Rahul?"* Hand it one lightweight index card at a time as the conversation progresses. Even with fixed model scaffolding (~500 tokens), keeping your active prompt at **~1,000 tokens/turn** instead of 4,500 slashes your per-turn prompt tax by **over 75%**.
</Aside>

### The Funnel Optimization

Rather than packing every conceivable instruction into a monolithic system prompt, **Just-in-Time (JIT) Prompt Cards** segment your agent's behavior into modular phase cards (`SOP_01_OPENING`, `SOP_02_DISCOVERY`, `SOP_03_PINCODE`, `SOP_04_BOOKED`).

### The 0–5 Second Drop &amp; The ~1,000 Token/Turn Realistic Floor

In real-world enterprise telephony (tele-sales, outbound screening, IVR bots, lead qualification):

> **30% to 50% of all phone calls drop within the first 0 to 5 seconds** (voicemail, immediate hangup, wrong number, prompt rejection).

#### 1. Protecting the 0–5s Bounce Zone
* **Monolithic Failure**: If you initialize a 4,500-token prompt on connect and the caller hangs up at 3 seconds, you pay for all 4,500 tokens. Across 40,000 bounced calls, that burns **180,000,000 wasted tokens**.
* **JIT Card 1 (`SOP_01_OPENING`)**: Contains only voice persona, opening greeting, and hook (~120 custom tokens + base scaffolding). Downstream objection matrices and booking schemas are never loaded on dropped calls—cutting bounce waste by **over 80%**.

#### 2. Active Turn Economics (~1,000 Tokens/Turn vs. 4,500 Tokens/Turn)
During active multi-turn conversations, your total prompt footprint per turn consists of:
* Fixed model-side scaffolding (~500 tokens on `gemini-3.1-flash-live`)
* Shared persona guardrails (~150 tokens)
* The active phase JIT card (~250 tokens)
* The single declared tool schema for the active phase (~100 tokens)

This yields a realistic active prompt floor of **~1,000 tokens per turn**. Across an 18-turn (3-minute) call, you bill **18,000 prompt tokens (`$0.014`)** instead of **81,000 prompt tokens (`$0.061`)**—a **77% reduction** in per-turn prompt tax.

---

### Dynamic Server-Side Card Injection &amp; Tool Thinning

Never rely on the model calling a tool to change phases—models frequently skip tool calls when users speak conversationally, and declaring 8 tool schemas upfront adds ~1,200 tokens of dead weight to every turn (**Single-Tool Hygiene**).

Instead, track phases on the server from the live user transcription stream and inject prompt cards dynamically via `send_client_content(turn_complete=False)`:

```python
# server/persona_prompt_cards/pragya_cards.py
CARDS = {
    "SOP_01_OPENING": """
    You are Pragya, a luxury automotive concierge.
    Greeting: "Hello! Welcome to Silver Star Concierge. Are you inquiring about the GT Roadster or our bespoke leasing?"
    Tone: Refined, crisp, polite. Max 1 sentence.
    """, # ~120 tokens

    "SOP_02_DISCOVERY": """
    Phase 2: Qualify Interest & Model Preference.
    Ask whether they prefer weekend touring or track performance.
    Answer model questions concisely.
    """, # ~280 tokens

    "SOP_03_PINCODE": """
    Phase 3: Delivery Location.
    Request caller 6-digit postal code for showroom allocation.
    Format: Listen for 6 digits. Do not accept partial postal codes.
    """, # ~310 tokens

    "SOP_04_BOOKED": """
    Phase 4: Final Booking Confirmation.
    Confirm showroom test drive schedule and state booking reference ID.
    """  # ~210 tokens
}
```

```python
# Injected into the active live session by the server
async def advance_phase_card(session, new_phase_id: str):
    card_content = CARDS.get(new_phase_id)
    if not card_content:
        return

    # send_client_content with turn_complete=False updates instructions without triggering output
    await session.send_client_content(
        turns=[{
            "role": "user",
            "parts": [{"text": f"[SYSTEM INSTRUCTION UPDATE - {new_phase_id}]:\n{card_content}"}]
        }],
        turn_complete=False
    )
```

<Aside type="caution" title="Funnel Telemetry Rule">
  Derive phase progression on the server using deterministic regex or transcript keywords (e.g. 6-digit PIN code detected $\to$ advance to `SOP_03`). Never force the LLM to call `get_phase_card()`, which adds turn latency and token schema overhead.
</Aside>

## Pillar 3: Client-Side Lossless Pruning

<Aside type="tip" title="Mental Model: Voice Memo vs. Text Note">
  Keeping historical user turns as raw audio in memory costs **\$3.00 / 1M tokens** on every subsequent turn. Converting older caller turns into text transcripts costs **\$0.75 / 1M tokens**—preserving the exact same conversation memory at **75% to 83% lower cost**.
</Aside>

### Lossless Client-Side Compaction

The server-side 5k sliding window is your hard ceiling, while client-side orchestration lets you compress historical memory with zero loss of customer context:

| Lever | Mechanism | Concrete Benefit |
| --- | --- | --- |
| **Transcribe, then Prune Audio** | Evict raw client PCM audio turns older than 2–3 turns; retain their text transcripts in history. | Spoken audio is re-billed at \$3.00/M tokens. Text transcripts cost \$0.75/M tokens. You get identical semantic grounding at **75%–83% lower cost**. |
| **Rolling Structured FactStore** | Maintain a JSON digest (`under 60 tokens`) of extracted user facts (`{name, pin, car_model, budget}`); re-inject each turn. | Survives 5k FIFO sliding window eviction. Even if Turn 1 was evicted 10 minutes ago, the agent remembers the caller's postal code and vehicle preference. |
| **Pin System Instructions** | Declare persistent constraints in `setup.systemInstruction`. | The built-in sliding window never evicts system instructions or pinned prefix turns. |

## TL;DR: The Unified Production Checklist

No single optimization solves telephony voice economics in isolation. Layer all three pillars into a unified production pipeline:

1. **0s – 5s (Call Inception — Pillar 2)**: Initialize with a featherlight `SOP_01_OPENING` card (~120 tokens) so the 30%–50% of calls that bounce in under 5 seconds burn virtually nothing.
2. **Turn 1 – Turn 3 (Funnel Progression — Pillars 2 &amp; 3)**: Keep active prompt overhead around **~1,000 tokens/turn** by injecting phase cards (`send_client_content(turn_complete=False)`) only when milestones advance, and prune caller audio older than 2 turns into text transcripts (**$0.75/M** instead of **$3.00/M**).
3. **Minute 2+ (Long-Call Safety Net — Pillars 1 &amp; 3)**: Configure server-side sliding window compression (`trigger_tokens: 5000`, `target_tokens: 3500`) to automatically flush stale turns while anchoring key entities in a `<60 token` FactStore.

> **The Production Golden Rule:**  
> *Start lean (Pillar 2), convert voice memos to text notes (Pillar 3), and put a sticky note on top of a 5k shredder (Pillar 1).* Together, these three patterns lock blended telephony costs at **~\$0.028 – \$0.035 / minute** while maintaining sub-600ms latency.
