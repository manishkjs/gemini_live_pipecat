Traditional voice architectures stitch together three separate cloud services: Speech-to-Text (ASR), a Large Language Model (LLM), and Text-to-Speech (TTS). Each service bills differently—ASR bills by the audio minute, the LLM by the text token, and TTS by the character.

**Gemini Live collapses the entire pipeline into a single native speech-to-speech model**, slashing latency and enabling natural, human-like voice conversations.

To help engineering and finance teams evaluate unit economics, Google publishes both **per-million-token prices** and **per-minute audio equivalents**. Understanding the mathematical relationship between these two metrics—and how live bidirectional conversations are metered—is essential for accurate telephony budgeting.

## 2. How the Per-Minute Baseline Is Derived

Telecom and CCaaS architects budget in **Cost Per Minute (CPM)**. The official per-minute audio figures represent a direct conversion of audio token velocity into clock time:

1. **Caller Audio Input (`~$0.005 / min`)**: Raw 16 kHz PCM audio streams into Gemini Live at approximately **27.8 tokens per second** (~1,667 tokens per minute):
   ```text
   1,667 tokens/min × ($3.00 / 1,000,000 tokens) = $0.005001 / minute
   ```
2. **Model Audio Output (`~$0.018 / min`)**: Generated 24 kHz PCM audio synthesizes at approximately **25 tokens per second** (~1,500 tokens per minute):
   ```text
   1,500 tokens/min × ($12.00 / 1,000,000 tokens) = $0.018000 / minute
   ```
3. **Continuous Single-Pass Baseline (`~$0.023 / min`)**: In a continuous, uninterrupted single-pass audio stream with zero turn-taking, pure audio processing totals:
   ```text
   $0.005/min (audio in) + $0.018/min (audio out) ≈ $0.023 / minute
   ```

## 3. Why Real-World Calls Diverge: The Four Billing Forces

When teams deploy voice agents into live customer service or sales telephony, they quickly observe that real phone calls bill higher than `$0.023/min`—often landing between **$0.08 and $0.20+ per minute**.

This divergence is not a billing error; it is the natural consequence of **four foundational forces** in stateful duplex tokenomics:

### Force 1: Turn-Based Re-Evaluation ("The Photocopier Effect")

Gemini Live does not meter by a wall-clock timer; it meters **per inference turn**.

Whenever the caller finishes speaking—or interrupts (barges in) mid-sentence—a **new model generation turn** is triggered. On *every single turn*, the model re-evaluates the entire active session context from scratch:
* Your `systemInstruction` (persona, SOP rules, guardrails)
* All declared tool JSON schemas
* The accumulated conversational history from all prior turns

### Force 2: Modal Memory Asymmetry (Caller Audio vs. Bot Speech)

One of the most important—and least understood—nuances of Gemini Live tokenomics is how the model stores **caller speech** versus **its own speech** in conversational memory across turns:

  <Card title="Bot Speech Collapses to Cheap Text" icon="approve-check">
    **$0.75 / 1M Tokens on Subsequent Turns**
    
    When the assistant speaks, you pay **$12.00/M** for audio generation on that turn. However, on all subsequent turns, the bot's audio is **automatically collapsed into a text transcript** (~0.25 text tokens per audio token) and re-billed at standard text input rates (**$0.75/M**).
  </Card>

  <Card title="Caller Speech Stays as Raw Audio" icon="warning">
    **$3.00 / 1M Tokens on Subsequent Turns**
    
    Unlike bot speech, **caller spoken audio remains in the context window as raw audio tokens**. On every subsequent turn, historical caller audio is re-evaluated at **$3.00/M**—making carried user speech **4&times; to 6&times; more expensive** per word than text memory.
  </Card>
</CardGrid>

### Force 3: Zero Default Prompt Caching &amp; Model Scaffolding

In standard batch request/response APIs, repeated static prompts frequently receive automatic context cache discounts. In real-time bidirectional WebSocket sessions (`BidiGenerateContent`), carried context is evaluated on demand at standard input rates (`cached_content_token_count: 0`).

Additionally, live audio models include fixed model-side scaffolding (~500 tokens per turn on `gemini-3.1-flash-live` and `gemini-3.5-flash-live`) that is billed alongside your custom prompt instructions on every turn.

### Force 4: The Telephony 0–5s Drop Distribution

In enterprise telephony (outbound qualification, customer support, appointment reminders), call duration follows a steep power-law curve: **30% to 50% of calls terminate within the first 5 seconds** due to voicemails, wrong numbers, or instant hangups.

If an agent initializes every WebSocket connection with a heavy 4,500-token monolithic system prompt and 8 tool declarations, **100% of that upfront prompt weight is billed on Turn 1**—even when the caller hangs up 3 seconds later.
