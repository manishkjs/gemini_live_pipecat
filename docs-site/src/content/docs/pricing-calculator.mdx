## How the simulator models multi-turn sessions

1. **Single-pass streaming baseline (`$0.023/min`)**: Models a continuous full-duplex baseline of 60 seconds of caller audio input (`~1,668 tokens` at `$3.00/1M` = `$0.005/min`) plus 60 seconds of model audio output (`~1,500 tokens` at `$12.00/1M` = `$0.018/min`) with zero turn re-evaluation overhead.
2. **System prompt & tool re-billing (`N` turns)**: On every turn `1..N`, the model re-reads your active system prompt and tool declarations at `$0.75/1M` text input tokens (modelled at the Gemini 3.1 Flash Live text input rate; `$0.50/1M` on 2.5 Native Audio).
3. **Carried Audio Tax (`N × (N - 1) / 2` pairs)**: Without context compression or history pruning, Turn `k` re-reads the audio and text tokens from all `k - 1` previous turns (`~235 carried audio tokens` from caller speech + played model audio at `$3.00/1M` + `~72 text tokens` at `$0.75/1M` per prior turn, modelled at the Gemini 3.1 Flash Live text rate; `$0.50/1M` on 2.5 Native Audio).
4. **Optimized Live column (JIT Cards + 5k Sliding Window)**: Trims active system instructions to modular phase cards (`~500 tokens` average across the call) and caps carried history with a `5,000-token` sliding window and `<60-token` FactStore, keeping per-minute cost flat at **~$0.031/min** regardless of call length.

For the full production implementation of each optimization column in the simulator, see [Optimization Patterns](/gemini_live_pipecat/optimization/).
