Some lines are the same on every call: the greeting, "One moment while I check that," or the goodbye. Gemini Live still generates them fresh each time. You pay output audio tokens for them, the caller waits for the model to start talking, and the audio stays in the history where it is billed again on later turns.

You can make these lines once with Gemini TTS, save the audio, and play the saved clip instead.

This works because Gemini Live and Gemini TTS use the same prebuilt voice names (for example Aoede, Puck, Kore, and Charon) and the same audio format: 24kHz, 16-bit, mono PCM. Chirp 3 HD voices use the same names too, such as `en-US-Chirp3-HD-Aoede`. If you use Chirp 3 HD through Cloud Text-to-Speech, request `LINEAR16` audio at 24,000 Hz. Then a saved clip can play in a Live call without any format conversion. The two models generate speech separately, so the voice can sound slightly different. Listen to both side by side before you ship.

## Where cached audio helps

### The greeting

1. When the call connects, add the greeting text to Gemini Live's history as a `role="model"` turn with `send_client_content(turn_complete=False)`. Do this before any caller audio reaches the session, so the model knows it already said hello before it can reply to anything.
2. Play the saved greeting clip. There is no model call, so the caller hears it right away.
3. If the caller cuts in, stop the clip. The model's history still holds the full greeting. It is harmless if the model thinks the caller heard the whole hello.

Many bots send a text turn like "Hello" at connect time so the model speaks first. Skip that here, or the model will greet the caller a second time.

### Wait lines during tool calls

Your media server can play a short clip like "Let me check that for you" while a tool runs. Gemini Live isn't involved, so the clip costs no tokens. Stop the clip as soon as model audio arrives. If you use this, remove the "say a short acknowledgment before calling a tool" rule from your prompt, or the caller will hear two acknowledgments.

### Repeated replies in a cascaded pipeline

In a cascaded pipeline (speech-to-text, then an LLM, then TTS), lines like "Could you spell that for me?" come up often. Cache the TTS audio under a key made from the normalized text, the voice, the TTS model, and settings like language, speed, and pitch. Don't save audio from a reply that the caller interrupted, or the cache will keep a cut-off clip.

## What a cached greeting saves

These numbers assume an 8-second greeting (about 25 words, like the one in the code below) and a 10-turn call. Audio is about 25 tokens per second, so the greeting is about 200 audio tokens.

| | Generated by Gemini Live | Cached clip plus text in history |
| :--- | :--- | :--- |
| Wait before the caller hears anything | The model's response time (see [Latency](/gemini_live_pipecat/latency-and-telemetry/)) | A memory or Redis read |
| Greeting output on Turn 1 | About 200 audio tokens at `$12.00/1M` = `$0.0024` | 0 tokens. You pay for the TTS clip once, when you make it |
| Greeting carried into turns 2 to 10 | About 200 audio tokens per turn at `$3.00/1M` = `$0.0054` over 9 turns | Only the greeting text (about 30 tokens), which the generated greeting also carries as its transcript |
| Caller hangs up during the greeting | You still paid for the greeting audio | No greeting output cost |

That's about `$0.0078` saved per 10-turn call, or about `$780` per 100,000 calls. If [Pillar 1](/gemini_live_pipecat/optimization/sliding-window/) drops the greeting from the window sooner, the carried part of the savings is smaller.

## Code pattern A: Add the greeting to history, then play it

This version uses the `google-genai` SDK directly. `play_chunk` is your own function that sends audio to the caller. Run `play_cached_greeting` as a task right after the session opens. Have your caller-audio loop wait on `caller_audio_ok` before it sends the first chunk, so the greeting is in history before the model can hear anything and the caller can still talk over the clip.

```python
import asyncio
from google.genai import types

GREETING_TEXT = (
    "Hi, thanks for calling Cymbal Fiber. This is Maya, your virtual assistant. "
    "This call may be recorded for quality. How can I help you today?"
)
SAMPLE_RATE = 24_000
CHUNK_BYTES = SAMPLE_RATE * 2 // 50  # 16-bit mono: 960 bytes = 20ms


async def play_cached_greeting(session, play_chunk, greeting_pcm: bytes,
                               caller_interrupted: asyncio.Event,
                               caller_audio_ok: asyncio.Event):
    """Tell Gemini Live it already greeted the caller, then play the saved clip."""
    # Send this first, so the model knows it said hello
    # before any caller audio can trigger a reply.
    await session.send_client_content(
        turns=types.Content(role="model", parts=[types.Part(text=GREETING_TEXT)]),
        turn_complete=False,  # add to history without asking for a reply
    )
    caller_audio_ok.set()  # safe to forward caller audio from here on
    for start in range(0, len(greeting_pcm), CHUNK_BYTES):
        if caller_interrupted.is_set():
            break  # the caller started talking, so stop the clip
        await play_chunk(greeting_pcm[start:start + CHUNK_BYTES])
```

## Code pattern B: Cache TTS in a Pipecat cascade

The community package [`pipecat-tts-cache`](https://github.com/omChauhanDev/pipecat-tts-cache) wraps any Pipecat TTS service. It builds the cache key for you and skips saving audio when an `InterruptionFrame` arrives. Check its README for the Pipecat versions it supports before you upgrade Pipecat.

```python
# pip install "pipecat-tts-cache[redis]"
from pipecat.services.google.tts import GoogleHttpTTSService
from pipecat_tts_cache import TTSCacheMixin
from pipecat_tts_cache.backends import RedisCacheBackend


class CachedGoogleTTS(TTSCacheMixin, GoogleHttpTTSService):
    pass


tts = CachedGoogleTTS(
    settings=CachedGoogleTTS.Settings(voice="en-US-Chirp3-HD-Aoede"),
    cache_backend=RedisCacheBackend(
        redis_url="redis://localhost:6379/0",
        key_prefix="pipecat:tts:",
    ),
    cache_ttl=604800,  # keep clips for one week
)
```

The Redis backend stores audio with Python `pickle`, so point it at a private Redis instance that only your bot can write to.

<h2 id="pre-speech-compliance-guardrails-200ms-jitter-buffer">
  Pre-speech compliance guardrails (200ms jitter buffer)
</h2>

In strictly regulated industries (banking collections, healthcare triage, insurance underwriting), compliance teams sometimes ask: *"How do we guarantee the native audio model never speaks a prohibited phrase or leaks PII?"*

Because Gemini Live emits `outputTranscription` chunks concurrently with `inlineData` audio frames:
1. Hold outbound 24kHz PCM audio frames in a 150ms to 200ms ring buffer in your media gateway (Pipecat `FrameProcessor` or custom WebSocket proxy).
2. Run a fast deterministic regex / Aho-Corasick guardrail check against the streaming `outputTranscription` text.
3. If a prohibited pattern is detected, flush the 200ms ring buffer before the audio reaches the telephony socket and trigger a corrective prompt or human transfer.
